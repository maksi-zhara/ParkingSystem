# Правила допустимости бронирования

Пакет ИСР: **A1** (задача 4). Истории: **ID-02** (серверная проверка ограничений),
**ID-07** (места, статусы, размеры), **ID-08** (рабочее расписание),
**ID-10** (профиль ТС и габариты).

Все проверки выполняются **на стороне сервера** при создании, переносе и продлении
брони, в том числе при прямом вызове API в обход интерфейса. Недопустимая запись
не создаётся.

## 1. Габариты ТС и места (ID-10, ID-07)

- ТС хранит габариты: ширина, длина (и, опционально, высота), положительные значения.
- Место хранит ширину и длину, положительные значения.
- ТС подходит месту, если ширина и длина ТС **не превышают** ширину и длину места:
  `spot.width >= vehicle.width` и `spot.length >= vehicle.length`.
- При несоответствии габаритов бронь отклоняется с понятной ошибкой.

## 2. Статус места (ID-07)

- Место может быть активно или отключено администратором.
- Отключённое место **не предлагается** для новых броней и не может быть
  забронировано.
- Размеры и состояние места задаёт администратор.

## 3. Рабочее расписание (ID-08)

- Расписание задаёт время работы парковки (по умолчанию 08:00–20:00, `Europe/Moscow`).
- Бронь допустима только в пределах рабочего времени **одного дня**: начало и
  окончание интервала должны попадать в рабочие часы и относиться к одной дате
  в часовом поясе парковки.
- Бронь за пределами расписания отклоняется сервером, в том числе при прямом
  вызове API.

## 4. Доступ к парковке

- Пользователь без доступа к парковке не может забронировать её места
  (см. `roles-and-permissions.md`).
- Администратор не ограничен проверкой доступа при создании специальной брони.

## 5. Порядок применения проверок при создании брони

1. Корректность периода (`startsAt < endsAt`, начало в будущем).
2. Период в пределах рабочего расписания.
3. Существование активного ТС пользователя.
4. Существование активного места.
5. Наличие доступа к парковке места.
6. Соответствие габаритов ТС и места.
7. Отсутствие пересекающихся активных броней.
8. Сохранение с контролем ограничения целостности БД (защита от гонок).

Порядок отражён на диаграмме `Sequence создание бронирования.drawio`.

## 6. Критерии приёмки

- Backend отклоняет бронирование без доступа, для отключённого места, при
  несоответствии габаритов и вне рабочего времени; недопустимая запись не создаётся.
- Отключённое место не предлагается для новых броней.
- Бронь за пределами расписания отклоняется сервером, в том числе при прямом
  вызове API.
- Система сохраняет одно или несколько ТС с положительными габаритами; чужие ТС
  недоступны для изменений; выбранное ТС участвует в проверке места.
