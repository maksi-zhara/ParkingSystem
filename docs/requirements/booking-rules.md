# Правила бронирования

Пакет ИСР: **A1** (задача 3). Истории: **ID-01** (запрет двойного бронирования),
**ID-03** (поиск доступных мест), **ID-04** (создание подтверждённой брони).

## 1. Интервал бронирования

- Бронь задаётся парой моментов времени `startsAt` и `endsAt` в часовом поясе
  парковки (`Europe/Moscow`).
- Обязательное условие: `startsAt < endsAt`.
- Интервал трактуется как полуинтервал `[startsAt, endsAt)` — момент окончания
  не считается занятым.
- Начало брони должно быть **в будущем** относительно текущего момента.

## 2. Пересечение броней (ID-01)

- Два интервала **пересекаются**, если у них есть общая ненулевая длительность:
  `A.startsAt < B.endsAt` и `B.startsAt < A.endsAt`.
- Для одного парковочного места среди активных броней (статус `RESERVED`)
  не может быть пересекающихся интервалов.
- При конфликте второй запрос отклоняется с ошибкой (HTTP 409), недопустимая
  запись не создаётся.
- Инвариант обеспечивается на двух уровнях:
  1. предварительная проверка в сервисе перед сохранением;
  2. ограничение целостности в БД (исключающий индекс `GiST` по интервалу),
     защищающее от гонок при одновременных запросах.
- Требование проверяется **конкурентным тестом**: при одновременных запросах
  на одно место успешной оказывается не более одной активной брони.

## 3. Статусы брони (ID-04)

| Статус | Значение |
| --- | --- |
| `RESERVED` | Бронь активна и занимает место |
| `CANCELLED` | Отменена пользователем или администратором |
| `COMPLETED` | Период завершён, бронь была использована |
| `EXPIRED` | Период истёк, место не занято |

Жизненный цикл и переходы между статусами приведены на диаграмме
`State жизненный цикл бронирования.drawio`. Ключевые переходы:

- создание брони → `RESERVED`;
- отмена (`cancel(reason)`) → `CANCELLED`;
- окончание периода (`endsAt < now`) → `EXPIRED`.

Только статус `RESERVED` участвует в проверке пересечений и учитывается
при поиске доступных мест.

## 4. Поиск доступных мест (ID-03)

Место считается доступным для пользователя на выбранный период, если
одновременно выполнены все условия:

1. место активно (не отключено);
2. у пользователя есть доступ к парковке места;
3. место подходит по габаритам выбранного ТС;
4. период попадает в рабочее расписание парковки;
5. на месте нет активной брони, пересекающейся с выбранным периодом.

Результат поиска учитывает период, активные брони, расписание, права доступа,
статус места и габариты ТС.

## 5. Операции с бронью

- **Создание** — при корректном запросе создаётся бронь со статусом `RESERVED`
  с указанием места, ТС и времени; пользователю показывается подтверждение.
- **Просмотр** — пользователь видит только свои брони (активные и историю).
- **Отмена** — владелец может отменить свою активную бронь; её интервал вновь
  становится доступным. Чужую бронь обычный пользователь отменить не может.
- **Перенос / продление** — при изменении места или периода повторно проверяются
  пересечения и остальные ограничения. При отказе исходная бронь остаётся
  корректной и неизменной.

## 6. Критерии приёмки

- Для одного места и пересекающихся интервалов одновременно успешна не более
  одна активная бронь; второй запрос отклонён; инвариант проверен конкурентным тестом.
- Результат поиска учитывает период, активные брони, расписание, права доступа,
  статус места и габариты ТС; покрыт положительными и отрицательными тестами.
- При корректном запросе создаётся бронь с местом, ТС и временем; при ошибке
  бронь не возникает.
