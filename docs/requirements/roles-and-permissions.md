# Ролевая модель и права доступа

Пакет ИСР: **A1** (задачи 1–2). Истории: **ID-05** (регистрация, вход, роли),
**ID-09** (выдача и отзыв доступа к парковке).

## 1. Акторы и роли

| Роль | Тип | Источник |
| --- | --- | --- |
| Гость | Неавторизованный пользователь | Story Map (роль 1) |
| Пользователь / водитель | Конечный пользователь (`TEACHER`, `TECHNICAL_STAFF`) | Устав, Story Map |
| Администратор парковки | Ключевой пользователь (`PARKING_ADMIN`) | Устав, Story Map |

Роль администратора парковки (`PARKING_ADMIN`) — единственная привилегированная роль.
Роли `TEACHER` (преподаватель) и `TECHNICAL_STAFF` (технический работник) дают одинаковые
права уровня «водитель»; разделение введено для классификации пользователей.

## 3. Правила доступа к парковке (ID-09)

- Доступ к конкретной парковке выдаётся пользователю администратором и хранится
  как связь «пользователь — парковка».
- Пользователь **без доступа** к парковке не может получить её доступные места
  и не может создать бронь места этой парковки.
- Пользователь **с доступом** видит только разрешённые ему парковки.
- Администратор имеет доступ ко всем парковкам без отдельной выдачи.
- Выдача и отзыв доступа выполняются пакетно: администратор задаёт список
  разрешённых парковок пользователя, система заменяет его целиком
  (см. `Activity выдача доступа к парковке.drawio`).
- Отзыв доступа не удаляет уже созданные брони, но запрещает создание новых.

## 4. Подход к авторизации

- Аутентификация — по email и паролю, пароль хранится в виде хэша (BCrypt).
- Результат входа — JWT access token; фронтенд хранит его в `localStorage`
  и передаёт в заголовке `Authorization: Bearer <token>`
  (см. `Sequence аутентификация.drawio`).
- Разграничение прав выполняется **на стороне сервера**: запрос к
  административному API без роли `PARKING_ADMIN` отклоняется (HTTP 403).
- Проверка прав доступа к парковке и бизнес-правил выполняется на backend
  (см. `admissibility-rules.md`), а не только в интерфейсе.

## 5. Критерии приёмки

- Реализованы регистрация и вход; роли пользователя и администратора различаются.
- Запрос к административному API без нужной роли отклоняется сервером.
- Пользователь с доступом видит разрешённую парковку; без доступа не может
  получить её доступные места или создать бронь.
